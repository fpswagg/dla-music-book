# Database (Prisma 7)

PostgreSQL through Prisma 7:

- `prisma/schema.prisma` — models; generator `prisma-client` writes to `src/generated/prisma` (git-ignored,
  regenerated by `pnpm build` / `pnpm db:generate`). Import from `@/generated/prisma/client`.
- `prisma.config.ts` — schema path, migrations folder, seed command and the datasource URL (`DATABASE_URL`).
- `src/lib/prisma.ts` — the client with `@prisma/adapter-pg`; `null` in demo mode.

## Migrations

The schema is changed only through migrations, so SPT backups/restores and deployments stay predictable.

```bash
pnpm db:migrate        # development: edit schema.prisma, then create + apply a migration
pnpm db:deploy         # production / CI: apply pending migrations (never creates any)
```

`prisma migrate dev` needs a shadow database (CREATEDB). If the database user cannot create one, generate the
SQL without it and review it before committing:

```bash
npx prisma migrate diff --from-schema <old schema> --to-schema prisma/schema.prisma --script > prisma/migrations/<timestamp>_<name>/migration.sql
```

Always read generated SQL: Prisma drops and recreates on renames (see `20261003200000_refonte`, edited by hand
to rename `UserProfile` to `User` instead of dropping it).

### Baseline of an existing database

Databases created earlier with `db push` already have the `0_init` tables. Mark the baseline as applied once,
then deploy:

```bash
npx prisma migrate resolve --applied 0_init
pnpm db:deploy
pnpm db:backfill --apply      # structured lyrics + search text for hymns written before the refonte
```

## Seed

`pnpm db:seed` (development only) upserts languages, tags, the four hymnals of the book, authors and a few
sample hymns (5–7 transcribed from a scan of the book, to proofread). It never overwrites existing hymns.
